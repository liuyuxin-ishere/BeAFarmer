## 1. 一句话定位

玩家在自己的小岛家园里**种地、采集、加工、完成订单**，并在**多人在线广场**与其他玩家社交；在既有基包桥接能力内，活动与抽卡内容通过 **Lua 业务、资源与兼容配置热更新**上线，无需重新安装。

> 本项目的灵感来自“装扮 + 经营 + 轻社交”类休闲游戏，所有名称、角色、美术、文案均为原创，不使用任何商业游戏的素材。

## 2. 项目目标：这个作品要证明什么

作品集项目的首要目标不是“做出一个能上线的游戏”，而是**用一个完整、可运行的项目证明工程能力**。

| 能力维度 | 通过什么功能证明 | 可展示的证据 |
|---|---|---|
| 客户端架构 | C# AOT / Lua 业务分层、生成桥接、模块化、事件驱动、数据驱动 | 架构图、代码结构 |
| 热更新 | Lua 业务 + 资源 + 兼容配置热更；既有桥接内不重装包上线新卡池 | 演示视频（改前 / 改后） |
| 联网与同步 | 广场多人同屏、AOI、分线、机器人压测 | 压测数据、录屏 |
| 服务端权威 | 服务器计时、订单校验、服务端抽卡 | 协议文档、时序图 |
| 性能优化 | 换装合批、对象池、图集、画质分档 | 优化前后性能对比表 |
| 数据驱动 | 配置表驱动全部玩法数值 | 配置表 + 导表流程 |
| 工程化 | 版本管理、自动构建、日志与文档 | 仓库与文档 |

## 3. 目标用户与使用场景

- **主要观众**：面试官 / 招聘方 / 同行评审。
- **使用场景**：
  1. 阅读 README 与文档了解设计与架构（5 分钟）。
  2. 观看 3~5 分钟演示视频。
  3. 在本机运行 Demo 亲自体验（可选）。
- **设计含义**：游戏必须能在 **10 分钟内**让陌生人看到完整闭环；不需要长线养成内容。

### 4.2 不做什么（Out of Scope）

> 此清单是单人项目防止范围蔓延的关键，**新增需求必须先对照此表**。

| 不做 | 原因 |
|---|---|
| 真实支付、充值、商城 | 不上线；抽卡使用游戏内虚拟货币 |
| 公会 / 家族、交易所、拍卖行 | 工作量大且与作品集目标关联弱 |
| 剧情主线、NPC 好感度 | 内容量大，价值低 |
| 小游戏合集 | 同上 |
| 完整运营后台 | 用调试面板与配置文件代替 |
| 多语言本地化 | 仅简体中文；文本仍走 key，预留扩展 |
| 反外挂、封号体系 | 仅做基础服务端校验 |
| 正式合规（防沉迷、实名、版号） | 不对外发布 |
| 多服务器集群与分布式 | 单进程服务端即可，文档中说明扩展方案 |
| 高精度美术 | 低多边形风格，控制工作量 |

## 5. 完成标准（Definition of Done）

### 5.1 项目整体完成标准

- [ ] 所有 P0 功能通过自测清单（见 `06_开发计划.md`）。
- [ ] 从全新账号开始，**10 分钟内**可完整体验：种→采→加工→订单→升级→进入广场→抽卡。
- [ ] 完成一次**纯热更**上线新卡池的演示（不重新打包客户端）。
- [ ] 广场机器人压测：单线 100 个连接稳定运行 30 分钟。
- [ ] PC 端：1080p 下平均 ≥ 60 FPS（广场 40 角色同屏）。
- [ ] 无阻断性崩溃；日志可定位主要问题。
- [ ] 文档齐全：本目录设计、开发计划与迁移说明 + README + 开发日志。
- [ ] 产出：演示视频（3~5 分钟）、截图 / GIF、可运行的 PC 构建。

### 5.2 单个功能完成标准

一个功能只有同时满足以下条件，才能打勾：

1. 功能规则按 `02_玩法设计.md` 实现；
2. 数值来自配置表，无硬编码；
3. 服务端校验到位（涉及资产、时间、随机的操作）；
4. 异常情况（断网、背包满、重复提交）有处理；
5. 自测清单对应条目通过；
6. 代码已提交，开发日志记录了关键问题与解决方式。

## 7. 技术与资源约束

| 项 | 约束 |
|---|---|
| 工具链 | Unity 6000.3、xLua（Lua53）、YooAsset；Framework / Shared / Config / Protobuf 保持 C# AOT。固定来源与平台验收见 [07](07_xLua迁移方案与PoC.md) |
| 服务端 | C#（.NET 8），单进程，SQLite 起步，可切换 MySQL |
| 美术资源 | 优先使用授权明确的免费 / 付费素材包，或自制简单低模；**在 README 列出所有素材来源与授权** |
| 开发时间 | 每周约 15~20 小时，总计约 8~9 个月（见开发计划） |
| 版本控制 | Git；大文件使用 LFS |

此次架构切换需要新的 xLua 基包：旧 HybridCLR 安装不能只收 Lua 补丁完成迁移。新开发基包 AppVersion `0.2.0`（`ProjectSettings.bundleVersion` 已生效）、ProtoVersion `1`；100→101 演示从新的 xLua 安装开始，实际结果见 [07](07_xLua迁移方案与PoC.md)。

## 8. 素材与版权策略

1. 不使用任何商业游戏的美术、音频、角色、名称与 UI。
2. 第三方素材必须确认**允许在作品集中展示**；记录名称、来源链接、授权类型。
3. 字体选用可商用的开源字体（如思源黑体）。
4. 在仓库 `ThirdParty-LICENSES.md` 中集中登记开源库与素材授权。

## 9. 风险与应对（单人版）

| 风险 | 概率 | 应对 |
|---|---|---|
| xLua 原生库、生成桥接及 YooAsset 与 Unity 6000.3 的兼容问题 | 中 | 真实 Windows IL2CPP 验证互调、整数、生命周期和补丁；Android / iOS 另验。失败保留证据，不套用历史 PoC 结论 |
| 范围蔓延导致无法收尾 | 高 | 严格对照“不做”清单；设砍功能线（见开发计划） |
| 美术拖慢进度 | 高 | 低模 + 素材包；先灰盒，最后统一替换美术 |
| 广场同步 bug 难排查 | 中 | 先做机器人与日志；同步逻辑保持简单（状态同步） |
| 动力衰减 / 战线过长 | 中 | 每 2 周一个可演示版本；每个里程碑有明确验收 |
| 移动端工作量超预期 | 高 | 列为 Stretch，不影响作品集主线 |
