## 1. 决策总表

| ID | 主题 | 冻结结论 | 来源 |
|---|---|---|---|
| D01 | operation_scope | 登录签发并持久化 `operation_scope_id`；Reconnect 恢复同一 scope；新登录关闭旧 scope 的新写权限。写命令身份为 `(player_id, scope_id, op_id)`，每 scope 的 op 从 1 单调递增 | 计划 §3.1 |
| D02 | 持久账本保留 | 详细 `command_receipt.result_blob` 仅保留 **7 天**（服务运行参数）；scope 墓碑与高水位永久保留。过期后同 key 不得二次执行，须返回过期/需同步 | 计划 §3.1 |
| D11 | Ack / 规范哈希 / Query | 摘要格式固定 **`cmdhash-v1`**；19 写 Resp 嵌 `CommandAck`；Query 追加 `result_state`+`ack`；Login/Reconnect/Sync 的 `next_op_id` 为 **proto3 optional int64**（`HasNextOpId`；拒绝/外 scope 不设置，不用 0 哨兵冒充缺省）；新登录 next=1，重连为存储实际值；旧 scope 只读查询；NotRecorded=code0+显式态；冲突优先于过期细节；**不**改 schemaVersion（保持 4） | T010；05 §1.5/§4.3 |
| D03 | 事务受理与取消 | 玩家队列内、账本未命中且 Domain/DB 事务**受理点之前**可因取消拒绝；**受理后**业务事务使用独立完成范围，窗口关闭/连接取消令牌不得中断提交 | 计划 §3.2；M1 §9.2 |
| D04 | 时区与日切 | 权威日历为 **UTC+8**；日切小时读 `Global.daily_reset_hour`（当前源表 **0**）。`day_index` 判定跨日；跨多日一次校正到当前日，不循环补发未领日奖 | 03 Global；计划 §3.4 |
| D05 | 订单可提交 / 可生产 | 分情形：库存充足保证 ≥2 条**真正可提交**且两条合并库存可同时满足；不足时 ≥2 条**已解锁可生产**并显式降级；空候选明确失败。禁止伪造库存/零需求/重复礼包凑指标 | 计划 §4.5；本文件 §3 |
| D06 | 奖励与容量 | 同一**业务命令**真正产生的多来源奖励（例：订单交付奖 + 同次触发的工具升级物品）经统一 `RewardPolicy` 做**最终容量预检**：仅当奖励含**物品**且会导致**新占格超限**时整笔拒绝（301），无局部入包。**货币/经验不占背包格**。每日 3/6 里程碑奖（03：券/钻，**无物品**）由独立命令显式领取（T055）；满包时纯货币领奖**应成功**，不得凭空给里程碑加物品，也不得因满包对纯货币返回 301 | 03 §8.3；计划 §4.1；T055；05 `ERR_BAG_FULL=301` |
| D07 | 建造时长 | 设施建造/升级 **即时结算**；不引入建造倒计时（03/设施表无建造时长字段） | 计划 §4.4 |
| D08 | 满级经验 | 最高等级 **20**（03 Level，曲线不变）。升至 20 时：`level=20` 且 **`exp` 清零**；之后任何经验增量**丢弃**（不累计、不溢出显示）。理由：满级后不再存在 `need(20→21)`，保留残留/溢出经验会误导 UI 与存档比较；清零使满级态唯一可测 | 03 §7.1 |
| D09 | 初始资产与 M1 迁移 | **新号**：货币=`new_player_*`（200/300/5）恰好一次；背包格=`bag_init_slots`；地块 6；工具 5101、5103 各 1；**种子列表为空**（买种起步）。**M1 已有玩家**：保留原货币/背包等既有值（例 gold=201），**不得**重置为 200，**不得**再加货币礼包。`grant_version` 只对**缺失的玩法域**做一次初始化（地块/工具/订单态等）；货币域若 M1 已写入则跳过 | 03；M1 持久化实况 |
| D10 | 等级奖励表 | 当前 03 **无**独立“每级物品奖励表”；Lv3 时赠送 5102×1。不擅自新增逐级礼包 | 03 Level/Item |

## 5. 追加（T009）：schema4 — Token↔operation_scope 显式关联

> **不改写** §上文及 T005 当时 schema3 历史验收语义。schema3 仍只表示：`command_scope` / `command_receipt` / `grant_version` / `server_clock_meta` 已存在；**不含** Token 与 scope 的持久外键。

### 5.1 决定

| 项 | 决定 |
|---|---|
| 版本号 | `SqliteStore.CurrentVersion = 4`；迁移路径保持 **0/1→2→3→4** 顺序；禁止把关联表“塞回” schema3 |
| 关联表 | 新建 `auth_token_scope`：`token_hash` PK；`FOREIGN KEY (token_hash, player_id) REFERENCES auth_token(token_hash, player_id)`（复合，禁止跨玩家挂靠）；`FOREIGN KEY (scope_id, player_id) REFERENCES command_scope(scope_id, player_id)`；`scope_id UNIQUE`（一对一 Token↔scope，墓碑行保留） |
| 旧行 | 迁移保留既有 `auth_token`、货币、snapshot、TokenHash；legacy允许**没有关联表行**。已存在关联行的`scope_id`是`NOT NULL`，不能用NULL绕过归属与唯一约束 |
| legacy 补全 | 仅**合格 M2** Reconnect 在 lane 内同事务 **CAS 一次**补 scope+关联；旧安装 106 不补；并发不双写 |
| 回滚 | `MigrateToCurrent` 单事务；任一步失败整迁回滚；未来 schema>4 拒绝且不改库 |
| 明文 Token | 仍不进 SQL/日志/账本；仅登录成功响应受限返回 |

### 5.2 迁移 / 回滚 / 拒绝测试要求

- 空库直接到 4；手写 schema1/2/3 夹具升级到 4 且 gold201 / bag1×7 / TokenHash / snapshot 字节不变。
- schema2→4及纯schema3→4分别预建冲突`auth_token_scope`，失败后版本各停留2/3；新索引/DDL一起回滚，旧资产和blob不变（T009最终实测）。
- `schema_meta.version=9` → 抛错、库不变。
- 重复 Initialize 幂等为 4。
